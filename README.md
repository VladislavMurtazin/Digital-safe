# Digital Safe - Локальный прототип (Zero-Knowledge)

## Главные принципы безопасности (СТРОГО СОБЛЮДАТЬ)

1. **Безопасный контекст**: Приложение должно запускаться через `http://localhost`, а не `file://`.
2. **Никаких внешних скриптов**: Не использовать CDN (ни Tailwind, ни шрифты). Только локальный CSS.
3. **Нет отдельного хеша пароля**: Не хранить хеш мастер-пароля в localStorage. Успешная расшифровка AES-GCM (отсутствие ошибки `OperationError`) является единственным доказательством правильности пароля.
4. **Нормализация пароля**: Перед любыми криптографическими операциями пароль должен проходить `password.normalize('NFKC')`.
5. **Стойкость KDF**: Использовать PBKDF2 с алгоритмом SHA-256 и **600 000 итераций**. Показывать спиннер загрузки, так как это займет 1-2 секунды.
6. **Структура данных**: Файл резервной копии называется `digital-safe-backup-YYYY-MM-DD.json` и содержит `{ version: 1, kdf: { algo: 'PBKDF2', hash: 'SHA-256', iterations: 600000 }, salt, data: { iv, ciphertext }, settings }`. Счётчик блокировки и открытый текст в файл не входят.
7. **Соль и IV раздельно**: Соль KDF (16 байт) создаётся один раз при создании сейфа и хранится открыто. IV (12 байт) создаётся заново при каждом шифровании. Повторное использование IV с тем же ключом недопустимо.

## Этап 1: Локальный MVP (Только клиент, без сервера)

### Задача 1: Базовая структура и стили

- Лендинг и страницы: `index.html`, `css/style.css`, `app/`, `how-it-works/`, `security/`, `pricing/`, `legal/`.
- Сейф: `app/index.html`. Криптоядро — `js/crypto.js`, экран сейфа и макет таймера — `js/app.js`, меню и форма email — `js/site.js`.
- Написать чистый, минималистичный CSS (темная тема по умолчанию, адаптивная верстка).
- Предупреждение на главном экране: "ВНИМАНИЕ: Это прототип. Забытый мастер-пароль означает БЕЗВОЗВРАТНУЮ потерю данных. Не используйте для реальных сид-фраз до финального аудита."

### Задача 2: Генерация ключа и шифрование (`js/crypto.js`)

- Функция `generateSalt()`:
  1. Вызывается один раз при создании сейфа.
  2. 16 случайных байт через `crypto.getRandomValues`.
  3. Соль не секрет. При следующем сохранении заметки она не меняется: ключ сессии уже выведен из этой соли.
- Функция `deriveKey(password, salt)`:
  1. `const normalized = password.normalize('NFKC');`
  2. Использовать `crypto.subtle.importKey` и `crypto.subtle.deriveKey` (PBKDF2, SHA-256, 600000 итераций, 256 бит).
  3. Ключ неэкспортируемый, только `encrypt` и `decrypt`.
- Функция `encryptData(plaintext, key)`:
  1. Генерация нового 12-байтного IV через `crypto.getRandomValues` на каждое шифрование.
  2. Шифрование через `crypto.subtle.encrypt` (AES-GCM).
  3. Возврат объекта `{ iv, ciphertext }` в base64. Соль в этот объект не входит.
- Функция `decryptData(encryptedObj, key)`:
  1. Попытка расшифровки.
  2. Если ошибка `OperationError` → вернуть ошибку "Неверный пароль или поврежденные данные".
  3. Если успешно → вернуть расшифрованный текст.

### Задача 3: UI и логика приложения

- **Экран 1: Создание/Вход**. Одно поле ввода мастер-пароля и кнопка "Открыть сейф".
  - Если в `localStorage` нет данных → создать новый сейф (сгенерировать соль, показать интерфейс создания).
  - Если данные есть → попытаться расшифровать их с введенным паролем. Успех = разблокировка. Ошибка = красное сообщение "Неверный пароль".
- **Экран 2: Сейф**.
  - Текстовая область для заметки.
  - Кнопка "Сохранить" (шифрует текущий текст, перезаписывает `localStorage`, показывает спиннер на время PBKDF2).
  - Кнопка "Очистить сессию" (Esc): очищает ключ из памяти, скрывает текст, возвращает на Экран 1. Данные в `localStorage` остаются зашифрованными.
- **Экран 3: Настройки DMS (UI-макет)**.
  - Поле "Интервал таймера (дни)".
  - Текст-предупреждение: "Для реальной работы Dead Man's Switch вам потребуется сгенерировать Ключ Восстановления и передать его доверенному лицу оффлайн. Сервер никогда не увидит этот ключ."
  - Кнопка "Сгенерировать Ключ Восстановления" (показывает длинную случайную строку для копирования).

Выбранный путь DMS для MVP: упрощённый вариант B. Ключ восстановления пользователь передаёт доверенному лицу сам, офлайн. Сервер позже хранит только зашифрованный сейф и таймер и после истечения таймера отдаёт сейф на скачивание по уникальной ссылке. Подтверждение «Я жив» делается кнопкой внутри приложения, не переходом по ссылке из письма. На этапе 1 у DMS только интерфейс и предупреждение.

### Задача 4: Экспорт и Импорт

- **Экспорт**: Считать зашифрованные данные из `localStorage`, добавить метаданные (version, kdf params, settings), преобразовать в JSON и скачать файл `digital-safe-backup-YYYY-MM-DD.json`. Счётчик блокировки в файл не входит.
- **Импорт**: Поле загрузки файла. Прочитать JSON, запросить мастер-пароль, попытаться расшифровать в памяти. Если успешно → заменить данные в `localStorage` и показать успех. Если нет → ошибка "Неверный пароль или поврежденный файл".

### Задача 5: Качество кода

- Использовать `async/await` и строгую обработку ошибок (`try/catch`).
- Никаких `console.log` для паролей, ключей или открытого текста.
- Код должен быть модульным (отдельные функции для crypto, ui, storage).

## Инструкции по запуску для разработчика

1. Не открывать HTML двойным кликом.
2. Использовать локальный сервер, например: `python -m http.server 8000`.
3. Лендинг: `http://localhost:8000/`. Сейф: `http://localhost:8000/app/`.
